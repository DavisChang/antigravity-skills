# ai-judge Skill（中文說明）

多 AI 裁判系統：讓多個 AI 候選者產出結構化解法（程式碼、架構、SQL、文件），透過程式化驗證（編譯、測試、lint、安全掃描）過濾，再由 AI 裁判依評分規則打分，最終精煉出完整交付物與審核報告。

## 這個系統「不是」什麼

- 不是單一 AI 挑自己喜歡的答案
- 不是聊天機器人包裝多個回覆
- 不是「看起來合理」的文字比較
- 不是直接把 AI 產生的 code 丟進正式環境執行

## 這個系統「是」什麼

多個 AI 候選者產出 **結構化輸出**（程式碼、架構、SQL、文件） → **程式化驗證** 過濾失敗的候選（編譯、測試、lint、安全掃描） → **AI 裁判** 依 rubric 評分並引用證據 → **精煉器** 修補贏家 → 系統交付 **完整套件**（artifacts + 決策報告 + 稽核記錄）。

## 核心設計

1. **初期強制收集資訊** — 在產生任何候選前，系統會收集問題描述、限制條件、交付物、驗收標準
2. **硬性關卡先於裁判** — 編譯失敗、測試不過、安全漏洞的候選直接淘汰，裁判看不到
3. **「無勝者」是合法結果** — 所有候選都不合格時，系統拒絕產出假勝者
4. **評分必須有證據** — 裁判的每一個分數都必須引用候選輸出中的具體內容
5. **統一 schema** — 所有候選使用相同格式，公平比較
6. **全程稽核** — 每個 prompt、回應、驗證結果、決策都有記錄

## 如何使用

在對話中提及 AI 裁判、多模型比較，或直接描述需求：

> 「用 AI 裁判系統比較三種 rate limiting 方案。」
> 「讓多個 AI 分別提出資料庫 schema，再裁決最佳方案。」
> 「我需要多個 AI 候選者分別設計登入系統架構，最後由裁判評分。」

## 管線流程

```
收集資訊 → 正規化任務 → 產生評分規則 → 平行產生候選
→ 驗證（關卡過濾）→ 裁判（rubric + 證據）→ 精煉（如需要）
→ 重新驗證 → 最終輸出（artifacts + 報告 + 稽核）
```

## 候選角色

| 角色 | 專注方向 |
|------|---------|
| 正確性優先 | 成熟模式、完整測試、保守穩定 |
| 安全性優先 | 威脅模型、防禦式程式碼、信任邊界 |
| 成本優先 | 最小基礎建設、務實取捨 |
| 速度優先 | 最快交付、精簡架構、明確升級路徑 |

## 設計原則

1. **驗證 > 裁判** — 程式化檢查比 AI 意見更重要。
2. **統一格式** — 所有候選用同一 schema，不搞文筆比賽。
3. **證據為本** — 每個分數都要引用，不靠直覺。
4. **安全失敗** — 無勝者、備援、人工升級都是一等功能。
5. **完整追蹤** — 每一步都可記錄、可重播。
